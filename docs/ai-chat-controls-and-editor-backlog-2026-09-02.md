## 1. Баг: агент спрашивает город, а выпадающего списка нет

### Что видно

На скрине живого чата (провайдер Gemini, 2026-09-02) агент пишет: «в каком городе или
районе Крыма вы планируете отдыхать?» — а под сообщением одна кнопка «Подбери маршрут».
Ни списка городов, ни модального пикера.

### Что происходит на самом деле

Проверено по коду, а не по симптому:

1. **Механизм выбора города на бэкенде есть.** `chat_actions.py:210` — в
   `_ASK_FIELD_DEFAULTS["city"]` лежат десять городов, а `_SHEET_TITLES = {"city":
   "Выбрать город"}` переводит блок в `layout: "sheet"`, то есть в модальный пикер,
   который мобилка умеет рисовать (`ChatActionsLayout.sheet`).
2. **Но сработал он не по тому полю.** `build_actions_block` берёт список из
   `ask_field`; если поле не `city`, чипы строятся общие. В итоге остался только
   `want_generate` → «Подбери маршрут».
3. **Значит расходятся текст модели и её же структурный ответ.** Gemini написала прозой
   про город, но в `ask_field` город не проставила. Проза и структура разъехались —
   ровно тот «флаг от ИИ», о котором говорил пользователь.

### Что делать

**1.1. Заставить модель заполнять `ask_field` достоверно.** Правка промпта плюс проверка
на стороне бэкенда: если `assistant_text` явно спрашивает про город, а `ask_field` не
`city` — доверять тексту. Дешёвая эвристика по ключевым словам («город», «откуда»,
«районе») уже есть в мок-репозитории мобилки, её можно перенести на сервер как
страховку. Важно: это именно фолбэк, основной путь — корректный `ask_field`.

**1.2. Добавить в бэкенд тип блока `select`.** Сейчас в `ChatBlockOut`
(`route_builder/application/schemas.py:222`) семь типов: `place_chip`,
`route_proposal_card`, `catalog_match`, `actions`, `slider`, `toggle`,
`recommendation_card`. **`select` отсутствует**, поэтому выпадающий список, уже
свёрстанный в мобилке (`SelectBlock` + `ChatSelectControl`, коммит от 2026-09-02),
живёт **только в моках** — с реального бэкенда он прийти не может.

Нужен `SelectBlockOut` симметрично мобильному: `id`, `label`, `options[{value,label}]`,
`value`, `placeholder`. И маршрутизация: при `ask_field == "city"` отдавать `select` со
списком городов вместо sheet-варианта чипов.

**1.3. Решить, что делать со sheet-пикером.** Сейчас город спрашивается модалкой, а
макет рисует выпадающий список прямо в пузыре. Два механизма на одну задачу — надо
оставить один. Предлагаю `select`, а `layout: "sheet"` вернуть к общему случаю «много
вариантов, не влезают в чипы».

### Тесты

- `ask_field == "city"` → в ответе блок `select`, а не `actions`;
- модель прислала текст про город без `ask_field` → фолбэк всё равно даёт `select`;
- битые `options` (без `value`) не доезжают до клиента;
- мобилка: тот же путь на `DATA_SOURCE=api`, а не только на моках.

## 3. Лендинг на крымтрип.рф

Домен куплен 2026-09-02. Punycode — `xn--h1adgncbn4e.xn--p1ai`.

### На чём делать

**Рекомендация: статический HTML + CSS, который раздаёт уже стоящий Caddy.**

Обоснование от нашей ситуации, а не от моды:

- страница **одна**, дизайн придёт от человека макетом — собирать под это сборщик,
  ставить Node на прод-хост и заводить пайплайн сборки значит потратить день ради нуля;
- Caddy на сервере уже держит TLS и ACME — добавляется один блок с `file_server`,
  никаких новых процессов и никакой памяти сверх уже занятой;
- нечего ломаться: нет рантайма, нет зависимостей, нет обновлений безопасности;
- деплой — это `scp` папки, откат — `scp` предыдущей.

**Когда пересмотреть:** если страниц станет больше трёх, появится блог или понадобится
переиспользовать шапку/подвал — тогда Astro (статика на выходе, ноль JS по умолчанию,
собирается на машине разработчика, на сервер едет та же статика). React/Next для
одностраничника — заведомо избыточно.

### Структура на сервере

```
/opt/crimeatrip-site/          # статика, владелец crimeatrip-deploy
Caddyfile:
  xn--h1adgncbn4e.xn--p1ai, www.xn--h1adgncbn4e.xn--p1ai {
      root * /opt/crimeatrip-site
      file_server
      encode zstd gzip
  }
```

### Что нужно от пользователя

1. **A-записи** у регистратора: `@` и `www` → `201.24.55.130`.
2. После этого Caddy сам выпустит сертификат (ACME, порт 80 уже открыт).

### Куда вешать API и админку

Решено ранее (см. переписку 2026-09-02): постоянный адрес API —
`api.xn--h1adgncbn4e.xn--p1ai`, потому что он **не должен больше меняться** (в APK
вшивается при сборке). `crimeatrip.ru`, если освободится 15 сентября, берётся под
маркетинг, а API не трогается.

Админку — на отдельный поддомен и **под ограничение по IP** прямо в Caddy (тем же
приёмом, что Gemini-релей): на запоминающемся домене она станет мишенью сканеров, а
сейчас её защищает только неприметный sslip-адрес.

## 4. Найденные баги при наполнении базы знаний (2026-09-03)

Не блокеры, но зафиксировать, чтобы не наступить снова:

**Апсерт `ingest_knowledge.py` не подчищает лишние `chunk_seq`.** Если для места
количество чанков в новом прогоне стало меньше, чем в предыдущем (например, из места
убрали шаблонное описание, и вместо двух секций осталась одна), старые чанки с
чанк-номерами сверх нового count остаются в базе как сироты — `_upsert_chunk` обновляет
только те `(doc_id, chunk_seq)`, что производит текущий прогон, и никогда не удаляет
лишние. 2026-09-03 это дало утечку: после починки фильтра шаблонных описаний
(`_has_real_description`) 7 чанков с `chunk_seq=1` остались с текстом заглушки, хотя
источник для них уже не генерировался. Почищены вручную; сам ингест это не умеет.
Нужно: перед вставкой новых чанков места удалять его старые `chunk_seq >= len(candidates)`.

**Разовое расхождение метаданных обогащения.** Три места (Ливадийский дворец, Херсонес
Таврический, Долина привидений) имели `content_enrichment_status = 'missing'` и
отсутствующий `prompt_version`, при этом `description` всё ещё содержал шаблон
«Описание сгенерировано автоматически…» — то есть статус сбросили, а сам текст не
почистили. Из-за этого фильтр по метаданным один раз пропустил утечку; исправлено на
прямую проверку текста как источника истины (`scripts/ingest_knowledge.py`).
