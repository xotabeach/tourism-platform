# Редизайн статей (блогов): модель контента v2 + экраны

**Дата:** 2026-09-01
**Статус (обновлено 2026-09-02): реализовано.** Бэкенд (миграции `0049_articles_v2`,
`0050_article_bookmarks`, модель контента, лайки, закладки, «Читайте также», ранг автора)
и мобильная часть (домен, карточка, экран чтения, редактор G.9, выпадающий список секций
в «Моих маршрутах») в коде, тесты зелёные. Карточка статьи 2026-09-02 переверстана ещё
раз, уже по присланному пользователем макету: фото сверху + белое тело (тег и дата поверх
фото, заголовок, лид, подвал «аватар + имя + ранг / время чтения / лайки»).
**Контекст:** после реализации G.7/G.8 (домен, репозиторий, экран чтения, комментарии
в `tourism-mobile/lib/features/articles/`) пользователь оценил результат как «слишком
сырой»: модели не хватает контента (только заголовок + текстовые/картиночные блоки), а
экраны выглядят бедно (пустые карточки без обложки, нет ни одного визуального акцента
кроме текста). Этот документ переопределяет модель контента и служит ТЗ для дизайн-макетов
(см. соответствующий Artifact-канвас) и для следующей волны реализации.

---

## Что уже верно и не меняется

Проверено в коде — не переделывать:

- **Обложка уже считается автоматически.** `Article.cover_media_attachment_id` — это
  «денормализованный указатель на вложение первого картиночного блока»
  (`content/infrastructure/models.py:73-76`), и `_refresh_cover()`
  (`article_service.py:616-629`) пересчитывает его при каждом изменении блоков. То есть
  стоит автору добавить фото — обложка на карточке появится сама. Проблема была не в
  бэкенде, а в том, что мобильная карточка v1 просто плохо показывает то, что есть.
- **Блочная модель для тела статьи (текст/картинка) остаётся основой** — расширяем набором
  новых типов блоков (ниже), а не переделываем структуру.
- **Модерация, квоты (3 статьи/24ч), окно удаления комментария (6ч)** — без изменений,
  бэкенд уже это делает и это не жаловались.

## Что не так — конкретно

1. Карточка статьи показывает только заголовок и имя автора — ни превью текста, ни тегов,
   ни времени на чтение. Рядом с карточкой маршрута (у которой есть теги, дистанция,
   сложность, рейтинг) статья выглядит пустой.
2. Тело статьи — только абзацы и фото. Нет цитат, списков, разделителей: длинный текст
   превращается в стену абзацев.
3. У статьи нет способа для читателя отреагировать (лайк) или сохранить на потом —
   единственное действие с контентом сейчас это комментарий.
4. Нет никакой навигации «еще почитать» — прочитал статью и упёрся в комментарии,
   в отличие от маршрута, где внизу есть «Похожие маршруты».
5. Нет категоризации — фида/поиска по темам не существует, все статьи одной длинной
   лентой без фильтра.

## Модель контента v2

### Новые поля Article (бэкенд)

| Поле | Тип | Источник | Зачем |
| --- | --- | --- | --- |
| `excerpt` | `str`, до 200 символов | автогенерация: первые ~200 символов первого `text`-блока, обрезка по границе слова | превью на карточке вместо пустого места |
| `reading_time_minutes` | `int`, вычисляемое | сумма символов всех `text`-блоков / 800 (≈ скорость чтения на русском), округление вверх, минимум 1 | ожидание по времени, как у любого блога |
| `tags` | `list[str]`, до 5 | автор выбирает при публикации из общего словаря | категоризация, фильтр в ленте |
| `like_count` / `liked_by_me` | `int` / `bool` | новая таблица `article_likes(article_id, user_id)`, unique constraint | минимальная реакция без необходимости писать комментарий |
| `view_count` | `int`, приблизительный | инкремент при `GET /articles/{id}` для опубликованной статьи, не хочет высокой точности — обычный счётчик без дедупликации по сессии | социальное доказательство на карточке/деталях |
| `is_featured` | `bool`, default `false` | админ-флаг (уже есть админ-раздел «Контент» для статей — добавить туда переключатель) | ручная редакционная подборка на верх ленты/профиля |

`excerpt` и `reading_time_minutes` — **вычисляемые, не хранимые** (пересчитываются при
каждой отдаче, как `average_rating` у отзывов) — не нужна инвалидация при правке текста.
`tags`, `like_count`/`liked_by_me`, `view_count`, `is_featured` — хранимые.

### Тег-словарь

Переиспользуем и расширяем существующий словарь тегов маршрутов
(`route_publish_screen.dart:648-659`: Природа, Пешком, С детьми, Водопады, Романтика,
Смотровые площадки, Леса, Море, История, Гастрономия) — читатель уже знает эти слова по
маршрутам, не нужно учить второй словарь. **Важно:** сегодня это приватный
`const _availableFilters` внутри `route_publish_screen.dart` — не экспортирован и нигде
не переиспользуется (есть ещё отдельный, более грубый список фильтров каталога
`routeCatalogFilters = ['Все', 'Море', 'Горы', 'Еда', 'Лес']` в
`route_catalog_filter.dart` — это другой список, не тот). Реализация должна сначала
вынести `_availableFilters` в общий модуль (например
`lib/core/domain/content_tags.dart`), а не копировать список второй раз. Добавляем
блог-специфичные теги, которых нет в маршрутном наборе:

```
Личный опыт, Лайфхаки, Бюджетно, Список мест, Один день, Мнение
```

Максимум 5 тегов на статью (как ограничение на входе — не даём превратить теги в
дублирующий заголовок).

### Новые типы блоков

Текущий `BLOCK_TYPES = ('text', 'image')` → добавить:

- **`quote`** — цитата с опциональной подписью (`text_content` = сама цитата,
  переиспользуем существующее поле; подпись — новое `caption` поле, до 80 символов,
  nullable). Визуально: крупный курсив, левая акцентная полоса, как уже есть паттерн
  `_ReplyComposerContext`/`_PublishedReplyContext` в отзывах — та же левая полоса,
  другой масштаб текста.
- **`list`** — маркированный или нумерованный список. `text_content` хранит пункты,
  разделённые `\n`; новое поле `list_style` (`bullet` | `numbered`). Ограничение — до
  15 пунктов, каждый до 200 символов (проверяется как часть валидации блока).
- **`divider`** — визуальный разделитель без содержимого, просто типовой блок, ничего
  не хранит кроме `block_type`.

`BLOCK_TYPES` становится `('text', 'image', 'quote', 'list', 'divider')`. Constraint
`block_shape` в БД нужно расширить: `quote` требует `text_content`, `list` требует
`text_content` + `list_style`, `divider` не хранит ничего.

### Похожие статьи

В конце статьи — блок «Читайте также» по тем же тегам (пересечение хотя бы одного тега,
исключая текущую статью), максимум 4 карточки, тот же паттерн, что
`_SimilarRoutesSection` в `route_details_screen.dart:743-820` (горизонтальный скролл,
full-bleed). Не отдельный ML-подбор — простой SQL по тегам, как рейтинг маршрутов
(«считать агрегатом при выдаче, не денормализовать»).

### Сохранённые статьи (bookmarks)

«Моё избранное» (`my_routes_screen.dart`, экран физически называется
`MyRoutesScreen`) сегодня — это **4 раздела**, не 3: Маршруты, Подписки, Места, История
(`enum MyRoutesTab`), переключаемые кастомными pill-чипами (`_TabRow`), не настоящим
`TabBar`. Разделы уже неоднородны по источнику данных: «Места»/«Маршруты» идут из
единого `FavoritesRepository` (агрегат `{routeIds, placeIds}`), а «Подписки» и «История»
тянутся из совершенно других провайдеров (`profileSubscriptionsProvider`,
`routeExecutionHistoryProvider`). Добавление 5-го раздела «Статьи» с отдельным
провайдером сохранённых статей (не втискивая его в `FavoritesRepository`) — это
продолжение уже существующего паттерна, а не новая архитектура.

### Лайк статьи

Профильный лайк (`profileLikeControllerProvider`) — **булевый флаг**
`liked_by_me` без счётчика, дергающий `PUT/DELETE /users/{id}/like` и обновляющий
состояние через `ref.invalidate` (не оптимистично). Для статьи нужен **параллельный**,
не переиспользуемый компонент: своя таблица `article_likes`, свой счётчик `like_count`,
свои эндпоинты `PUT/DELETE /articles/{id}/like`. Форму контроллера (AsyncNotifier +
toggle) стоит скопировать, а вот оптимистичное обновление лучше сделать сразу — лайк
должен откликаться мгновенно, ожидание рефетча на каждый тап будет ощущаться медленным.

## Экраны (для дизайн-макетов)

### 1. Карточка статьи (переиспользуется в ленте, профиле, «Читайте также»)

Сейчас: обложка (часто пустая, просто иконка) + заголовок в 2 строки + имя автора.

Новая версия:
- обложка на всю ширину карточки (16:9), с лёгким градиентом снизу для читаемости тега
  поверх фото;
- один тег-чип поверх обложки, в углу (первый тег статьи);
- заголовок (2 строки, жирный);
- `excerpt` — 2 строки, вторичным цветом текста;
- нижняя строка: аватар + имя автора слева, «X мин чтения» и (если есть) счётчик
  лайков/сердечко справа.

### 2. Профиль — секция «Мои статьи» / «Статьи»

Сейчас: заголовок секции + горизонтальный скролл карточек, без пустого состояния.

Что добавить в макет:
- при количестве статей > 3 — верхняя строка с заголовком секции и ссылкой «Все» справа
  (как у секции «Достижения» на этом же экране — `context.pushNamed(achievements)` с
  текстом «Все» + шеврон, тот же паттерн);
- в «Мои статьи» (свой профиль) — статусные бейджи поверх карточки, а не только текстом
  внизу: черновик/на модерации/отклонена/опубликована, разными акцентными цветами.

### 3. Экран чтения статьи

Сейчас: обложка, заголовок, автор, блоки (текст/картинка), карточка «о маршруте»,
разделитель, комментарии.

Что добавить в макет:
- строка тегов под заголовком (чипы, как `AppFilterChipBar`, но не интерактивные на
  экране чтения — чистое отображение);
- время чтения рядом с датой публикации в строке автора («12 авг 2026 · 4 мин чтения»);
- панель реакций сразу под метаданными автора: лайк (сердце, счётчик, тап = toggle) +
  счётчик просмотров (глазок, только отображение, не интерактивный);
- рендер новых блоков — цитата (крупный курсив + левая полоса), список (буллеты/номера
  с отступом), разделитель (тонкая линия с воздухом сверху/снизу);
- «Читайте также» — горизонтальный блок карточек статей перед комментариями.

### 4. Редактор статьи (новый экран — сейчас не существует, это G.9)

Состав, который нужно нарисовать:
- поле заголовка сверху со счётчиком символов;
- панель выбора тегов (до 5, chip-toggle, из словаря выше);
- список блоков с drag-handle слева у каждого блока, кнопкой удаления справа;
- нижняя панель добавления блока — 5 иконок: текст, картинка, цитата, список,
  разделитель;
- для картиночного блока — состояние «загрузка…» / «повторить» на плашке блока (см.
  бэкенд-грабли: файл грузится отдельным запросом после создания блока);
- привязка к маршруту/месту — единый селектор с явным «или/или» (радио, не чекбоксы);
- нижняя панель: индикатор автосохранения слева («Сохранено» / «Сохранение…»), кнопка
  «Отправить на модерацию» справа, задизейблена пока нет ни одного блока с содержимым.

## Открытые вопросы (нужно твоё слово)

- **Байесовское сглаживание/сортировка по лайкам** — не в v2, только счётчик и toggle;
  сортировка ленты по популярности — отдельная задача, если появится сама лента статей.
- **Список мест (`list` блок с привязкой к местам, не просто текст)** — заманчиво для
  формата «топ-5 смотровых», но это уже почти отдельный тип блока с медиа на пункт;
  в v2 список — просто текстовые пункты, без вложенных карточек мест.
- **Есть ли отдельная лента/каталог статей** (не только «в профиле» и «на странице
  маршрута»)? Этот документ пока не проектирует отдельный таб/экран каталога статей —
  если он нужен, это отдельный экран поверх той же модели, не блокирует v2.
